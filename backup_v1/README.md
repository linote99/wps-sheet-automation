# WPS 表格固定流程处理器

这是一个面向 Windows 11 + WPS 表格的独立 GUI 工具：选择模板、三个源 XLSX、输出目录与文件名后，按固定流程清理模板副本、复制源数据、填充公式、调用 WPS 重算，再将指定公式列的当前计算值写入目标列。原模板和源文件保持不变，输出为新文件。

## 默认流程与可配置项

- 源工作簿可分别选择，也可选择同一文件夹自动匹配 `1.xlsx`、`2.xlsx`、`3.xlsx`。自动匹配仅查找这些确切文件名。
- 默认源数据从第 **2** 行开始，完全空白的数据行会跳过，其余有数据行按原顺序紧凑复制。
- 默认目标为模板前三个子表，依次为 `1当天派单`、`2当天归档`、`3装移全业务在途`。模板前三个子表顺序必须和填写的目标工作表名一致。
- **处理副本前，清除每个目标工作表中保留标题行之后的旧单元格内容，保留格式。** 默认第 1、2 表保留前 2 行并从第 3 行开始写入；第 3 表保留前 3 行并从第 4 行开始写入。每表的“起始行”同时是该表的公式种子行；种子行中配置公式范围内的公式会在清理时保留，并用来填充数据行。标题行数和每表起始行均可在 GUI 单独修改。
- 默认公式区及结果映射分别为 `EB:EN` 中的 `EJ → DG`、`EB:EU` 中的 `EQ → DG`、`EB:FV` 中的 `FQ → DG`。
- 可配置源工作表起始行、数据复制列起始/末列，以及每个目标表的模板工作表名、源工作表名、保留标题行数、数据/公式起始行、公式范围、结果列和粘贴列。
- **源工作表名称与数据复制末列没有默认值，必须由使用者确认填写。** 工具不会猜测，也不会默认复制到未经确认的末列。源数据默认起始行是 2；如果模板公式所在行不等于各表起始行，应先调整模板或把“公式种子行”布置在起始行，因为当前流程明确使用每表起始行作为公式种子行。

GUI 中可点击“保存当前配置”。用户配置保存于 `%USERPROFILE%\\.wps_sheet_automation.json`，不包含工作簿内容。输出文件名若未写扩展名会补上 `.xlsx`；已存在的目标文件会报错停止，不会覆盖。

## 运行要求与安全行为

需要 **Windows 11、已安装并能正常启动的 Windows 版 WPS 表格、Python 3.10 或更新版本**。程序通过 WPS 表格 COM 自动化执行完整重算，并在同一 WPS 会话内以 `Value2` 将计算结果写为值，避免用 openpyxl 二次保存造成公式缓存丢失。程序尝试 `ket.Application`、`ET.Application`、`et.Application` 三种 WPS ProgID；若均无法连接，会显示明确的 COM/ProgID 错误、各 ProgID 的异常详情和修复提示，不会改用 Microsoft Excel。

工具仅接受无宏 `.xlsx`，会拒绝包含外部工作簿链接的文件，以及模板中检测到的外部工作簿公式引用或 `WEBSERVICE`、`FILTERXML`、`RTD`、`CALL` 等外部访问函数；WPS 打开文件时也会禁用链接更新、事件和宏安全级别（若 WPS 暴露相应属性）。**源工作簿不会交给 WPS 执行公式**：源公式单元格只读取文件中已保存的计算缓存，若没有缓存就按空值复制并在日志提示。模板公式则交由本机 WPS 重算。

处理前会检查文件有效性、四个输入是否互不相同、工作表名称与顺序、公式种子行每个公式单元格、公式范围/结果列、复制区域是否碰到公式区域、映射目标是否会覆盖复制数据，以及输出路径是否已存在。清理和填公式只在同目录临时副本中进行：清除保留标题行以外的单元格值/公式、超链接和批注，但不移除格式；每表起始行的公式种子区域保留。复制数据只写单元格值，不主动复制源格式。全部步骤成功后才发布新输出；失败时清理临时文件并报告具体原因。

## 在 Windows 上安装依赖与打包

1. 在 Windows 11 上安装 Python 3.10+ 和 WPS 表格。
2. 双击 `install_and_build.bat`。脚本创建 `.venv`、安装 `requirements.txt`、运行静态检查与单元测试，并用 PyInstaller 生成 `dist\\WpsSheetAutomation\\` 程序目录。
3. 首次使用建议先按下文创建并处理假数据。程序运行时仍要求本机安装 WPS 表格及可用的 WPS COM 自动化组件；打包不会把 WPS 一并包含。

如需仅从源码启动，在该目录运行 `python main.py`。在非 Windows 环境，程序只允许运行 `python main.py --self-check` 静态检查，不会启动处理流程。

## 假数据测试

1. 安装依赖后运行 `python make_fake_data.py`。脚本会在 `fake_data/` 生成 `template.xlsx`、`1.xlsx`、`2.xlsx`、`3.xlsx` 和空的 `output/`；工作簿仅含虚构编号、姓名与测试公式，并在模板保留标题区、种子公式、格式及若干旧值供验证。
2. 打开程序，选择 `fake_data/template.xlsx`，点击“从文件夹自动匹配”并选择 `fake_data/`，输出目录选 `fake_data/output/`，输出名使用 `demo_result.xlsx`。
3. 设置复制列为 `A` 至 `C`，三个“源工作表”都填写 `示例源表`；默认三行保留标题/起始行分别是 `2/3`、`2/3`、`3/4`。检查映射为 `EJ→DG`、`EQ→DG`、`FQ→DG` 后开始处理。
4. 确认输出文件存在且原四个输入文件未变化；用 WPS 打开输出，核对第一、二表从第 3 行、第三表从第 4 行开始各有 3 条假数据，保留标题没有改变，公式区计算完成，DG 与各自结果列显示的内容一致；检查标题行下的旧测试值已清除且单元格格式保留。再用同一输出文件名运行一次，应收到“不覆盖已存在文件”的提示。
5. 可先把一个“源工作表”改成不存在名称，或把模板公式种子行改成不含公式的行，分别确认程序在发布输出前给出明确错误；失败后输出目录不应留下 `.staging.xlsx` 临时文件。

静态检查：`python main.py --self-check`；单元测试：`python -m unittest -v test_static.py`。单元测试中的 openpyxl 临时工作簿检查仅验证清理/复制/公式填充的文件准备阶段，不代替 WPS 真机重算验收。

## 当前交付验证范围

交付环境为 Linux，不具备 Windows WPS COM。因此此处只能运行 Python 语法、默认配置与列映射静态检查，并可测试不依赖 WPS 的临时工作簿准备阶段；**未在 Win11+WPS 真机上运行、未连接 WPS COM、未执行假数据端到端 WPS 重算，也未产出经验证的 EXE**。用户需要在 Windows 11 + WPS 上确认 COM ProgID 可连接、WPS 版本的重算/保存/值写入行为、假数据结果、模板公式兼容性及打包程序启动。
