# WPS 表格多源汇总处理器

这是面向 **Windows 11 + WPS 表格 + 无宏 XLSX** 的 GUI 工具。程序以模板临时副本处理数据，模板和源工作簿原件不会被覆盖；正常情况下，终端输出成功后才提交完整工作簿。若 WPS 已成功计算并保存、但后续 PNG 图片导出失败，程序仍会保留已保存 XLSX，并在错误提示中给出准确路径。

## 窗口尺寸与滚动（v7）

主窗口可拖动调整宽度和高度，默认尺寸为 **1500×960**，最小尺寸目标为 **1024×680**；启动时会按当前屏幕可用尺寸安全收缩默认值或已保存尺寸。超出可视区域的主界面内容可通过水平/垂直滚动条查看，扩大窗口时配置区和日志区会随之扩展。上次窗口宽高会独立保存到用户配置目录（Windows：`%APPDATA%\WpsSheetAutomation\window_size.json`；其他平台：`$XDG_CONFIG_HOME/wps_sheet_automation/window_size.json` 或 `~/.config/wps_sheet_automation/window_size.json`），该文件仅包含 `width` 和 `height`，不保存模板、源文件或其他敏感路径；损坏/不合法尺寸会回退到安全默认值。此窗口状态与业务 JSON 配置版本 v7 无关。

## GUI 可配置内容

### 源文件与目标表

- **输出文件名**：选定模板后，输出名默认更新为模板的完整文件名（含 `.xlsx`），例如 `装移机在途通报V92026.10.5.xlsx`；可在“输出文件名”框中手动改名。自动默认名会随模板切换，用户明确编辑过的自定义名则保留。命名配置保存了“自动/自定义”状态：载入自动命名配置时采用本次选定模板的文件名，载入自定义命名配置时保留配置内名称；旧配置会按旧通用默认名和模板文件名作兼容判断。输出与模板同目录且文件名相同会明确拒绝，绝不覆盖模板；可改名或选择其他输出目录。
- **目标子表**：可添加、删除目标表，分别设置模板工作表名、标题行数、粘贴起始行和公式列范围。界面只读显示公式模板行，它始终自动等于粘贴起始行减 1。
- **同表多源**：每个目标表可添加多份源文件，逐份设置文件路径、源工作表、复制起始行和结束行，并可调整源顺序。源工作表留空时使用该源工作簿的第一张表；同一目标表中后续源的数据会紧接前一源向下追加，不会覆盖前一源数据。
- **复制列**：全局设置复制起始列和末列，适用于所有源。结束行留空时从复制起始行扫描源工作表全部已使用列；遇到整行全空白，以其上一行为末行，边界后的数据不纳入。中间存在整行空白时，应填写显式结束行或移除空行。复制范围内其他空白记录会跳过并紧凑追加。
- **公式和结果列映射**：每张目标表可设置多条“公式结果列 → 目标列”，可选按值或文本写入。映射在首次完整重算之后写入；目标可落在源复制列内并覆盖复制值，但不能位于必须保留的公式列，也不能和同表其他结果映射写入相同目标列。

公式模板从**粘贴起始行的上一行**读取：例如 `start_row=3` 时使用第 2 行，`start_row=4` 时使用第 3 行。程序检查公式范围内每一列的模板单元格；如有缺失，会列出具体列和模板行。填充范围严格为 `start_row` 到追加数据的末行，不会清理或覆盖模板公式行；粘贴起始行必须至少为第 2 行。

### 模板内部两阶段范围映射

“前映射”和“后映射”是模板工作簿内部的独立规则，分别选择源工作表/范围与目标工作表/范围；源、目标区域的行数和列数必须相同。每条规则可选择不同工作表，不与某一份外部源文件绑定。

- 前映射源值在清理模板临时副本前读取；临时副本清理目标表旧内容后，先应用前映射，再写入主源数据。复制到目标的公式会按相对位置调整引用。
- 后映射在主源写入、公式填充及首轮 WPS 完整重算后执行；若后映射或之后的区域处理可能影响公式，程序会再触发一次完整重算。为避免漏掉依赖关系，当前实现统一在这些写入步骤后再完整重算。
- 在创建/修改临时工作簿前会检查前映射目标是否与实际主数据复制区、公式填充区、结果列映射或后映射目标重叠；发现冲突会明确报告并停止，避免意外覆盖。前/后映射的目标区域各自也不能互相重叠。
- 后映射目标不能覆盖保留公式区域，也不能和结果列映射目标重复。

### 三类独立的区域处理功能

`TextToColumns`、`Deduplicate` 和 `FormatConvert` 在 JSON 和 GUI 中是**三个独立功能**，各有启用开关和独立的规则列表；每个列表可添加、编辑、删除、上移/下移及保存/载入。工作流默认顺序仍为 **TextToColumns → Deduplicate → FormatConvert**，但可在“模块工作流”标签中调整；区域内的多条规则按各自列表顺序执行。模块位于后映射之后、工作簿最终保存之前，与源文件项无关。若规则区域相互重叠而顺序会先改写分列输入或占用分列目标，配置校验会明确指出冲突及必须的先后关系。

- **TextToColumns（文本分列）**：选择模板工作表、单列源范围、分隔符、输出起始列，并逐个指定结果列格式（`text`、`number`、`date`）。目标范围按实际拆分列数和源行数计算；目标非空、有公式、与源区域/公式区域重叠或超出 XFD 时会拒绝写入，不会静默覆盖。结果不足的单元格留空；拆分列数超过已配置格式数时会明确报错。
- **Deduplicate（去重）**：选择工作表和需处理的矩形区域，设置是否有表头，并选择按所选区域整行判重或按区域内一个/多个指定 Excel 列作为键。去重稳定保留首次出现的记录；有表头时保留首行。为保持工作表结构和格式，不删除整张表的物理行，而是在选择区域内紧凑保留记录并清空重复记录留下的末尾单元格；全空行不作为重复记录删除。选择区域含公式时会拒绝处理。
- **FormatConvert（格式/值转换）**：选择工作表和范围，将值转换成 `text`、`number` 或 `date`，同时设置对应的 Excel 数字格式；其他单元格样式尽量保留。数字支持千位逗号文本；日期支持日期单元格、Excel 日期序号、`YYYY-MM-DD`、`YYYY/MM/DD` 和 `YYYYMMDD`。无法转换的单元格会指出区域内相对行列并中止，不会静默变为空值。含公式单元格会拒绝转换。

区域处理可改变公式所依赖的输入单元格。后映射和全部已启用区域处理规则执行后，程序再次请求 WPS 完整重算，等待完成并保存；图片与文本读取都在这次保存之后进行。

### 图片和文本终端输出

- **图片 PNG 输出**：可添加任意多项模板工作表/区域配置。处理并保存工作簿后，程序使用 WPS 区域截图导出 PNG 到所选输出目录。若选择范围与合并单元格相交，会只读检查并反复扩大本次导出矩形，直到完整包含所有相交合并区域；`统计!AH1:BO44` 与标题合并区 `AH1:CL1` 相交，因此完整保留合并区域时实际截图必须扩为 `统计!AH1:CL44`。配置范围不会被改写，日志/文件名显示实际范围；程序不会暗中裁切合并单元格。若必须严格止于 BO 列，需接受不包含该合并标题的另一截图范围，或先在模板设计中调整合并布局。闭包扩展后仍执行图片尺寸安全限制。导出始终使用 WPS 当前行列隐藏状态，**不会临时取消隐藏或更改工作簿的隐藏属性**。文件名包含工作表名、实际区域和序号；若文件已存在会使用额外序号后缀，绝不覆盖。WPS 图片导出使用与所选范围同尺寸的临时图表作为图片容器；会激活可用的 WPS/工作簿/工作表/图表对象、选择区域、短暂泵送 COM 消息，并最多尝试三轮 `CopyPicture → Paste → Chart.Export`：先屏幕位图，再 `xlPicture`，最后重试位图。每轮都会清理临时图表和 PNG。失败提示同时包含闭包后的实际范围、用户配置范围及各轮阶段错误；仍失败时按原策略保留 WPS 已保存的 XLSX。
- **文本预览/复制**：可添加多项工作表/范围。完成保存后，GUI 显示每个区域的二维内容；每项都有单独的“复制”按钮。剪贴板文本按行换行、列间使用 Tab 分隔，空单元格保留为空字段；不生成文本文件。
- **终端阶段顺序与失败处理**：WPS 完成最终公式重算并保存后，程序才执行 PNG 导出和文本区域读取；此阶段不再改动工作簿。正常完成时，临时 XLSX 在两类终端输出成功后才提交到最终文件名。若 PNG 导出失败，程序会将 WPS 已保存的 XLSX 安全提交到最终文件名并保留，错误提示明确包含 XLSX 已保存及完整路径；本轮已生成的图片仍按失败清理。若文本输出失败，则继续采用原策略：清理临时 XLSX 和本轮图片，不发布最终 XLSX。WPS 保存成功前发生错误也会清理临时 XLSX。所有文件均以独占方式创建，已有输出绝不覆盖。

### 模块化工作流

“模块工作流”标签会显示当前执行模块，并提供**添加、移除、上移、下移**操作。模块包括模板清理、前映射、多源复制、公式填充、首次完整重算、结果列映射、后映射、文本分列、去重、格式转换、最终重算并保存、图片 PNG 输出和文本剪贴板输出。可选模块只有在从工作流移除且对应配置为空/关闭时才可省略；必需的清理、复制、公式、结果映射与最终保存步骤不能删除。

工作流允许用户调整独立步骤的先后次序：三类区域处理模块可互换，图片与文本只读输出可互换。正确性依赖不可颠倒：模板清理先于前映射和数据写入；多源复制先于公式填充；公式填充和首次完整重算先于结果映射；后映射及区域处理先于最终重算/保存；图片与文本输出都必须在最终保存之后。程序会在保存配置或开始处理时检查这些依赖；无效顺序会标出冲突模块、应有先后和原因。若分列与去重/格式转换规则区域重叠，还会检查规则级输入/目标冲突，而不只是模块名称顺序。

### 区域选择器与大范围安全限制

`TextToColumns`、`Deduplicate`、`FormatConvert` 和图片/文本输出共用自定义范围选择器；前映射/后映射仍使用普通 A1 矩形范围，不适用以下单点快捷语法。

- 单点 `A1`（优先级最高）表示整张工作表；单点 `A5` 表示第 5 行；单点 `D1` 表示 D 列。
- `B3` 或显式相同端点 `B3,B3` 表示单格；两个不同端点如 `D8,B3` 或 `D8:B3` 表示矩形并自动规范化端点顺序。
- 校验 Excel 最大列 `XFD`、最大行 `1048576`；超限坐标和非法端点会在处理前拒绝。
- **图片**为保护 WPS `CopyPicture`/图表资源，最多支持 2,000 行、2,000 列且合计不超过 100,000 格；整行/整列/整表快捷选择若超限会明确拒绝，应改选较小矩形。
- **文本输出**的整行/整列/整表请求会裁剪到该表实际已用范围；每个区域最多 100,000 格、2,000,000 个字符。显示和剪贴板复制按每块最多 500 行分块进行，用户可以选择块并分别复制；超出上限时需缩小区域。
- **区域处理规则**每条最多 500,000 格。常见大区域会明确拒绝，避免 COM 传输和内存耗尽。

### 配置保存与载入

“保存配置…”可导出 JSON，“加载配置…”可载入；“保存为默认配置”写入当前用户配置。GUI 另提供**新建并保存、保存当前、载入所选**命名配置功能，可保存并选择多份配置；配置库存放在用户目录 `~/.wps_sheet_automation_profiles/`。首版旧 JSON 仍会自动迁移。`default_config.json` 提供三张示例目标表，新增映射、输出与处理功能默认关闭或为空。

模板选择器按所选文件的文件名（不含扩展名）前 **N** 个字符匹配已保存命名配置所关联的模板文件名；N 默认 5，可在模板区编辑为 1–120。唯一匹配时询问是否载入，多份匹配时弹出选择框；无匹配时提示并保留当前界面配置，不会悄悄套用其他配置。模板匹配依据配置保存时的 `template_path`，因此命名配置名称可由用户任意自定义。

配置版本为 7。配置中的 `start_row` 只表示粘贴起始行，不配置公式模板行；模板行由程序自动计算为 `start_row - 1`。v6/v7 旧工作流配置仍可载入：旧 `start_row` 值作为粘贴起始行保留，并提示按上一行读取公式；任何旧公式种子行字段都会被忽略，不会用于选取公式。主要新增字段如下：

## 执行顺序与安全行为

1. 校验配置、模块工作流与模板/源文件，读取前映射源范围；依赖检查会阻止会导致错误结果的模块顺序。
2. 在输出目录创建模板临时副本，仅清理配置目标表标题行以下的旧内容；保留自动确定的公式模板行及其内容。
3. 按有效工作流应用前映射，并按每个目标表的源列表顺序追加源数据。
4. 从粘贴起始行上一行读取公式并填充到新增数据末行（不含模板行），在 WPS 首次完整重算，然后写入公式结果列映射及后映射。
5. 按工作流中配置的次序运行已启用的文本分列、去重和格式转换规则；再次请求 WPS 完整重算并保存工作簿。
6. 按工作流次序导出图片 PNG、读取文本区域；此后不再改工作簿。全部成功后把暂存工作簿提交为新的 XLSX；若 PNG 导出失败，则仍提交并保留 WPS 已成功保存的 XLSX，同时在错误中报告完整路径。文本读取失败维持原有策略，不发布 XLSX。

程序要求 Windows 版 WPS 表格 COM，不会改用 Microsoft Excel。仅接受无宏 XLSX，拒绝外部工作簿链接和检测到的外部引用/外部访问公式；打开 WPS 时尝试关闭链接更新、事件和宏安全选项。外部源公式按 XLSX 已保存的缓存值读取，缺少缓存时作为空值复制并记录提示。

模板/源文件在交给 openpyxl 前会使用受限 ZIP/XML 临时副本处理。程序拒绝路径穿越、重复/加密 ZIP 成员并限制成员数量和解压大小；若工作表级筛选范围无效，只在临时副本移除该筛选定义。仅严格合规的整行 `sortState` 引用（例如 `3:393`）会转换为等价 A1 区域（`A3:XFD393`）；其他无效排序引用会明确报错且不会静默删除。源读取和模板 staging 使用临时副本上下文统一登记 openpyxl workbook，并在退出上下文、删除副本前逐个 `close()`；Windows 共享锁会进行有限短重试。模板/源文件原件不改写。

处理中间副本若经过短重试后仍被占用，程序会记录带完整路径的清理警告，要求关闭占用程序并手动删除；该警告不会把已成功的读取/处理变成失败，也不会覆盖读取阶段原本的错误。WPS 保存前失败会清理中间 XLSX；文本输出失败仍清理中间 XLSX 和本轮已生成图片且不发布最终文件。**只有 PNG 输出失败这一终端错误例外：已由 WPS 成功保存的 XLSX 会被保留，并在提示中给出完整路径**；本轮图片仍会清理。已有最终输出文件和已有同名图片均不会覆盖。图片由 Windows WPS COM 导出；系统剪贴板由 GUI 的 Tk/Windows 剪贴板接口写入。

## 安装、运行与测试

需要 Windows 11、Python 3.10+ 和 WPS 表格。首次安装时，在解压后的项目目录双击 `install_and_build.bat`。它会创建或复用项目内 `.venv`，将依赖安装到该环境，先检查 `pythoncom`、`win32com.client` 和 pywin32 版本，再运行语法、自检和单元测试，最后由 PyInstaller 构建 `dist\\WpsSheetAutomation\\`。安装/构建输出会追加保存在 `install_and_build.log`；若脚本失败，窗口会显示失败步骤并暂停，检查该日志中的 pip、导入或构建错误后再重试。只有出现 `Build complete` 才表示脚本流程成功结束；这不代表已在目标电脑验收 WPS COM 或 EXE。

每次源码运行都双击同一目录中的 `run_app.bat`。它会用本目录 `.venv\\Scripts\\python.exe` 检查 COM 导入并启动 `main.py`，不依赖当前目录或系统 `PATH`。**不要直接双击 `main.py`，也不要用系统 Python 执行 `python main.py`**：那会绕过安装器中的 `.venv`，即使 `.venv` 已正确安装 pywin32，系统 Python 仍可能报 `No module named 'pythoncom'`。若误用其他 Python 启动，错误弹窗会列出当前解释器的完整路径和正确入口；若通过 `run_app.bat` 仍缺少依赖，请检查 `install_and_build.log`。Linux 等非 Windows 环境不能运行 WPS COM 主处理流程，可运行：

```bash
python3 main.py --self-check
python3 -m unittest -v test_static.py
```

测试使用自动生成的虚构 XLSX、假 WPS/COM 对象和模拟 PNG 导出器；覆盖窗口尺寸、配置往返、命名配置、工作流依赖与区域处理、映射、多源追加、公式处理、范围限制、PNG/剪贴板和失败清理行为。文件名回归验证模板选择时自动采用模板 basename、模板切换更新自动名但保留用户显式自定义名、profile 中自动/自定义标记的载入优先级、旧配置迁移，以及模板同目录同名时明确拒绝且原模板字节不变。图片回归验证多重合并闭包和真实示例 `统计!AH1:BO44 → AH1:CL44`、用户配置范围不变、模拟隐藏行列状态不变、闭包后的尺寸限制、备用 `CopyPicture` 格式和瞬时 `Chart.Export` 失败重试；端到端用例确认 PNG 最终失败后 XLSX 仍存在、可读取且提示含准确路径，WPS 保存前失败仍不发布，文本输出失败仍清理。公式回归覆盖 `start_row=3`/`4` 分别读取上一行、公式相对引用下填、模板行不变、`start_row=1` 拒绝、缺失列和旧 v6/v7 配置迁移。临时副本测试还验证源读取/模板 staging 在成功和异常路径都先关闭 workbook 再删除，并模拟 Windows 文件共享锁验证短重试、残留文件警告和处理结果不被误判。假 WPS 仅用于可重复地检查范围、隐藏状态、命名与调用顺序，不等同真实 WPS COM。
